# Synty Local Dex — standalone sibling-folder edition

A local, file-derived asset explorer inspired by SyntyDex. It works with your existing downloads and does **not** use the Synty website or any credentials. Only the Local Dex files are included in this release; **`SyntyDownloader` is not replaced or modified**.

## Expected layout

The three directories are **siblings** under any parent directory, drive or network location:

```text
<any-parent>/                       (for example D:\Synty\)
├── SyntyDownloader/                existing downloader, unchanged
│   ├── synty_sync.py
│   ├── run_synty_sync.ps1
│   └── .venv/Scripts/python.exe     used by Dex if available
├── SyntyLibrary/                   existing downloads, read-only to Dex
│   ├── POLYGON - Adventure Pack/
│   │   └── POLYGON_Adventure_SourceFiles_v3.zip
│   ├── ANIMATION - Bow Combat/
│   ├── .synty_history.json         owned by downloader
│   └── .synty_browser_profile/     owned by downloader
└── SyntyLocalDex/                  this tool
    ├── build_local_dex.py
    ├── local_dex_server.py
    ├── local_dex_web/
    ├── open_local_dex.cmd
    ├── rebuild_local_dex.cmd
    ├── sync_and_rebuild_dex.cmd    optional: sync then index
    └── .localdex/                  generated *here* by first index
        ├── index.sqlite3
        ├── catalog.json
        └── covers/
```

**The parent directory need not be `D:\Synty`**. You can move all three folders together to e.g. `E:\Projects\Synty` without changing configuration or commands. The Python scripts compute the default library location from **their own file location**: `SyntyLocalDex/../SyntyLibrary`. The `.cmd` files find a Python executable in `../SyntyDownloader/.venv/Scripts/python.exe` first, then fall back to `py -3` or `python` from PATH (Python 3.10+). No PowerShell execution-policy changes are needed to run the Dex browser or indexer.

## Install or upgrade **only the Dex**

1. Unzip `SyntyLocalDex_Sibling_Folders.zip` into the directory that *contains* your three Synty folders. Its only top-level item is `SyntyLocalDex/`.
2. Keep your original `SyntyDownloader/` and `SyntyLibrary/` as they are; no need to re-download files.
3. Double-click **`SyntyLocalDex/rebuild_local_dex.cmd`** to build the initial index.
4. Double-click **`SyntyLocalDex/open_local_dex.cmd`** to open **http://127.0.0.1:8765** in your browser. Leave the command window running while using the browser; press Ctrl+C to stop.

The generated SQLite catalog and cover cache belong to `SyntyLocalDex/.localdex` rather than the download folder. An old `SyntyLibrary/.localdex` generated by an earlier Dex version is **not** used or removed by this upgrade; you can manually archive it after confirming the new catalog works.

## Update catalog after downloading new packages

Pick either workflow:

- **Separate steps:** run your existing downloader as usual, then run `SyntyLocalDex/rebuild_local_dex.cmd` (or click **Refresh index** inside the Dex browser).
- **Combined, optional launcher:** run `SyntyLocalDex/sync_and_rebuild_dex.cmd`. It starts the sibling downloader's `run_synty_sync.ps1`, with `--output` directed to `../SyntyLibrary` through its `-OutputDir` argument, **then** rebuilds the Dex catalog on successful completion. This launcher doesn't change the downloader's script or settings and requires its existing virtual environment and PowerShell sync script.

Indexing is incremental: unchanged archives are skipped using file path, size and modification time. The indexer does **not** delete, move, extract or overwrite your downloads. It may prune obsolete *database records* if source files were removed by some other process.

## Python direct usage (no `.cmd` needed)

Open a terminal inside `SyntyLocalDex/` and use your existing Python 3.10+:

```powershell
py -3 .\build_local_dex.py
py -3 .\local_dex_server.py
```

To index more quickly by skipping individual asset paths inside Unity packages:

```powershell
py -3 .\build_local_dex.py --skip-unity-contents
```

For nonstandard layouts, paths can still be overridden:

```powershell
py -3 .\build_local_dex.py --root "E:\OtherAssets\SyntyLibrary" --index-dir ".\.localdex"
py -3 .\local_dex_server.py --root "E:\OtherAssets\SyntyLibrary" --index-dir ".\.localdex" --port 8765
```

Note that `--index-dir` must be **outside** the assets folder. The relative default remains recommended.

## Browser features

- Pack browsing grouped by inferred collection (`POLYGON`, `ANIMATION`, `INTERFACE`, etc.) and theme.
- Search individual asset paths inside `.zip`, `.unitypackage`, and already-extracted directories.
- Type/category/engine hints inferred from filenames and paths (not authoritative Synty metadata).
- Source path inspector and *Show source in Explorer* to open/select local archives.
- Pack preview image when usable artwork is present in the downloads.
- Index refresh from browser, localhost-only HTTP server (`127.0.0.1:8765`).

The indexer requires only the Python standard library. `.rar` and `.7z` packages are cataloged but not inspected internally; nested archives are not recursively processed. It previews supported images and static OBJ/FBX geometry, but does not reproduce full FBX materials, animation or native engine scenes; it is not a pixel-perfect clone of official SyntyDex.

## Security and local data

No Synty password or browser session is read by Local Dex. Only file names, relative paths and archive entries are indexed. The browser is bound to localhost and uses a request token for sensitive actions. The generated catalog and covers are stored in the Dex folder, not under `SyntyLibrary/`.

## Tests

```powershell
py -3 -m unittest discover -s tests -v
```

The tests cover package discovery, incremental indexing, ZIP/Unity filenames, local APIs, request authorization, sibling-folder resolution and separation of generated catalog data from original downloads.

## Asset cards and offline FBX previews (October 2026 update)

Asset cards maximize the preview area. The filename (including its extension) is shown by hovering over the **ⓘ** icon at the bottom right, next to the type and engine tags. The former asset name, pack name and footer rows have been removed from cards; these details remain in the right-hand inspector.

FBX files are supported in the inspector as **interactive shaded 3D static mesh previews** (drag to rotate, scroll to zoom), with automatically generated mesh thumbnails in the asset grid. They work with loose `.fbx` files and `.fbx` members inside `.zip` and `.unitypackage` archives. Python decompresses only the selected archive member **in memory**; no extracted files are written to your downloaded library. The only new generated files are SVG thumbnails under `SyntyLocalDex/.localdex/fbx_thumbs/`.

The lightweight bundled FBX geometry reader handles common binary FBX 7.x and ASCII FBX 7.x mesh data. A shaded Canvas renderer is used when WebGL is unavailable. It does **not** recreate source materials/textures, scene node transforms, rigging or skeleton/keyframe animation. Some older or nonstandard FBX exports and animation-only FBX files cannot produce a mesh preview. A clear error is shown instead. Large previews are capped (96 MB uncompressed, 180k vertices and 125k triangles); oversized or complex files may be refused or simplified. No cloud services, external JavaScript libraries, Blender or new pip packages are required.

**Installation:** Exit the running Dex server and extract the changed-files-only update over your `SyntyLocalDex` directory. Relaunch `open_local_dex.cmd`. A catalog rebuild is not required just for this UI/preview update, since FBX entries were already indexed. Rebuild if you added downloads in the meantime.
